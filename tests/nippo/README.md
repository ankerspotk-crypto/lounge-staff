# 日報の自動テスト

```bash
node tests/nippo/run.js          # 全部
node tests/nippo/run.js 05       # 05_back だけ
```

**⚠️本番シートにも `_TEST` シートにも一切書かない。** 偽シート（`tests/pos/lib/gasstub.js`）の上で
`nippo.gs` の**実物のコード**を eval して走らせる＝ロジックを書き写していないので、
実装を直せばテストが即追随する。

## 何を守っているか

| suite | 守るもの |
|---|---|
| `01_calc` | **TRUSTと同じ数字が出ること**。基準は TRUST 実画面 2026-08-27 の実データ（`TRUST日報仕様.md`）。深夜跨ぎ・分あんぶんの端数・日払い控除。 |
| `02_prefill` | **黒服にゼロから打たせない**。シフト／打刻／名簿／伝票からの下ごしらえ。退職者・休み・シフト外の扱い。 |
| `03_save` | **取り直しても増えない**・**画面の計算値を信用しない**・保存済みが下ごしらえに勝つ。 |
| `04_lock` | 確定した日は書き換えられない。解除しても監査の跡は消えない。同時保存のロック。 |
| `05_back` | バック自動計算。**出典を混ぜない**（POSがあればPOS／無ければTRUST伝票）。 |
| `06_front` | **画面とサーバの計算が一致すること**（＝一番大事）。`GUNSHI_API_FNS` と `KEEP_PREFIX` の登録漏れ検出。連打で二重送信しない。 |

## ⛔ 触るときの決まり

- **計算式は画面(`gunshi-test.html` の `npCalcRow`)とサーバ(`nippo.gs` の `nippoCalcRow_`)の2箇所にある。**
  片方だけ直すと、黒服が見た額と給与に入る額が食い違う。`06_front` の契約テストだけがそれを見つける。
  **どちらかを直したら必ず両方直して、このテストを通すこと。**
- backend に関数を足したら `GUNSHI_API_FNS` に登録する（`06_front ①` が検出する）。
- 永続プロパティを足したら `resetGunshiSettings_` の `KEEP_PREFIX` に足す（同上）。
